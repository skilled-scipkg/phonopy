# phonopy: API and Scripting

## High-Signal Playbook

### Triage questions
- CLI workflow or Python API workflow?
- Which calculator interface and structure format are used?
- Are displacements generated by phonopy or provided externally?
- Are forces imported from parser outputs or custom arrays?
- Are results needed as YAML artifacts, plots, or in-memory arrays for downstream code?

### Canonical workflow
1. Choose front-end:
   - `phonopy`: pre-process and force import (`-d`, `-f`, `--fc`).
   - `phonopy-load`: post-process from `phonopy_xxx.yaml` artifacts.
   - utility scripts: `phonopy-gruneisen`, `phonopy-qha`, plotting scripts.
2. In Python, read structure via `read_crystal_structure(...)` and instantiate `Phonopy(...)` with calculator context.
3. Generate displacements (`generate_displacements`), write supercells, run external force calculations.
4. Set `phonon.forces` or `phonon.dataset`, then `produce_force_constants()`.
5. Run analysis (`run_band_structure`, `run_mesh`, thermal properties) and save `phonopy_params.yaml`.

### Minimal working example
```python
import numpy as np
from phonopy import Phonopy
from phonopy.interface.calculator import read_crystal_structure

unitcell, _ = read_crystal_structure("NaCl.in", interface_mode="qe")
phonon = Phonopy(
    unitcell,
    supercell_matrix=np.diag([2, 2, 2]),
    calculator="qe",
    set_factor_by_calculator=True,
)
phonon.generate_displacements(distance=0.03)
phonon.save("phonopy_disp.yaml")
```

### Pitfalls and fixes
- Wrong unit conversion in API runs: set calculator context and `set_factor_by_calculator=True` for non-default calculators (docs: `doc/phonopy-module.md`, `doc/interfaces.md`).
- Deprecated factor usage (`--factor`/`factor=`): avoid new use; rely on calculator defaults (docs: `doc/changelog.md`, `doc/command-options.md`).
- `phonopy-load` called like `phonopy -c`: `phonopy-load` does not provide `-c` and expects yaml-driven context (docs: `doc/phonopy-load.md`, `doc/command-options.md`).
- Force import fails: keep `phonopy_disp.yaml` in cwd when building `FORCE_SETS` (docs: `doc/input-files.md`, examples: `example/NaCl-QE/README.md`, `example/Si-CP2K/README.md`).
- Optional tooling unavailable (e.g., pypolymlp): gate features with dependency checks.

### Convergence and validation checks
- Verify `phonon.calculator` and unit conversion factor are what you expect.
- Confirm force constants shape (`(N,N,3,3)` or compact `(Np,N,3,3)`) before analysis.
- Check saved yaml artifacts (`phonopy_disp.yaml`, `phonopy_params.yaml`) round-trip with `phonopy.load`.
- Use focused regression tests when changing parser/API behaviors.
